# 这次评测为什么没有正确评估 skill

**结论先行：** 这次的分数和 Δ **不能用来判断 `graphviz` / `model-architecture` skill 的好坏**。评测衡量的主要是"Opus 能不能读懂源码"和"信息密集的大图在缩小后好不好读"，而 skill 声称提供的价值（统一的画图规范、正确的适用范围、出图速度）大多没有被计分，或者根本没有测到。下面逐条说明。

## 1. 计分维度和 skill 的价值错位

分数由三个评分器组成，其中没有一个是对准 skill 本身的：

| 评分器 | 实际测的是什么 | 对 skill 的区分力 |
|---|---|---|
| render | 有没有生成 PNG | 18/18 都通过，**没有区分力** |
| correctness | Opus 读源码、把机制画全的能力 | 18/18 都通过，**饱和**；skill 本来就不负责理解代码 |
| readability | 评委对缩小后大图的版式判断 | 主要取决于题目信息有多密、用什么工具排版（见第 4、5 条），而不是 skill |

skill 真正提供的东西，例如统一的节点语义分类（7 类）、模板配色、"架构用 Graphviz、UML 用 Mermaid、模型内部用 TikZ"的分流规则、更快出图，**要么没有评分器，要么只作为不计分的指示器**。速度和花费的优势（G 类快 45%）测到了，但不进分数。

## 2. 没有测 skill 自己声明的行为

- **规范是否被遵守**：没有任何评分器检查节点是否按 7 类语义分类、是否沿用模板配色、是否用了正确的模板。A3 带 skill 的组用 Python 生成 `.dot` 时用了自己的配色，评测里完全看不出来。
- **该不该触发**：SKILL.md 明确写着 UML 时序图和活动图不要用 Graphviz。但 G1、G2、G4 正是流程题和时序题，skill 在这些题上触发了，`skill-fired` 指示器却把它记成"正确"。评测缺少"本不该触发"的题，也缺少相应的判定。

## 3. 题目分布偏离 skill 的设计范围

- 9 个 case 里有 4 个（G1–G4）是流程、时序或混合题，在 graphviz 的设计范围之外；只有 3 个（A1–A3）是架构题，而且**没有一道纯依赖图题**。
- 每个 prompt 都要求"Ground every element in the code"，并要求覆盖 4–5 个机制。结果两组都把大量 `file:line` 和调用链塞进节点，图的长边做到 3000–4500 px。skill 的模板是为中等规模、清爽的拓扑概览设计的，这种"信息越多越好"的题目本身就不利于测出它的长处。

## 4. 对照组混入了"工具选择"这个变量

不带 skill 的组可以自由选工具，结果有 4/9 次改用 Pillow 手工排版。所以这次比较的其实是"Graphviz + skill 规范"对"任意工具 + 手工排版"，而不是"同一工具下有无规范"。按最终工具统计，readability 通过率是 Graphviz 3/12、Pillow 3/4，**这个差异两组都受影响，和 skill 关系不大**。要测出 skill 的作用，应该再加一个同工具的对照组：不带 skill，但同样用 Graphviz。

## 5. 评委本身的问题

- 评委看到的是缩到长边约 2000 px 的 JPEG，原图越大扣分越多，所以 readability 很大程度上在测图的尺寸。
- 评委和画图的 agent 是同一个模型（Opus）。
- 评委的理由没有被保存（JSON 和 HTML 里都只有投票），所以无法复核每次判定的依据。
- 和人工判断有明显分歧：G3 评委判 3:0 对 0:3，用户认为打平；G1、G2、G4 评委没分出高下，用户认为不带 skill 的泳道更清楚。

## 6. 样本量

每个 case 每组只跑了 1 次。G1 跑过三次，带 skill 组的 readability 结果就翻转过一次。单个 case 的 Δ 没有统计意义，9 个 case 的平均 Δ（−0.11）也落在噪声范围内。

## 7. 补充指标都比较粗糙

- **风格一致性**只统计色相直方图，不看形状、版式和节点分类。
- **看图评分**和**内容可读性**是 Claude 打的分，和被测 agent 属于同一类模型，不能代替人工打分。
- 人工美观打分（PLAN 第 9 步）没有做。

## 这次评测仍然可以采信的部分

- **路由**：9/9 都触发了对应的 skill，没有误用另一个 skill（但见第 2 条：流程题本不该触发 graphviz）。
- **效率**：只算 agent 本身，带 skill 合计 1514 秒 / $9.63，不带 skill 2086 秒 / $10.65；流程 / 时序 / 混合类 4/4 都更快更省，A1 的耗时和花费都约为不带 skill 的一半。M 类反过来更慢。
- **定性观察**：各 case 的 `notes.md` 和 `content-review.json` 里记录了两组图的视角差异，例如 G3 一张是"结构 / 依赖图"、一张是"流水线讲解图"。这些描述本身是准确的。
- **产物完整**：18 张最终图、源码（`.dot` / `.tex` / `.py`）和 trace 都保存在 `cases/` 里，可以拿来做人工盲评或重新评分。
